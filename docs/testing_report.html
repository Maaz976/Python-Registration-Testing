2.2 Workflow used

  1. Read the SRS and derive expected outcomes before inspecting implementation branches.
  2. Design ECP, BVA, and decision-table cases in workbooks and implement them in tests/test_blackbox.py.
  3. Execute the black-box suite, preserve all failures, and open one GitHub Issue per distinct defect.
  4. Inspect source code, draw the CFG, calculate V(G), and design condition/MC-DC analysis.
  5. Add structural tests in tests/test_whitebox.py and measure initial/final coverage.
  6. Fix confirmed defects on defect-fixes, one commit per defect, and rerun the complete suite.
  7. Record final coverage and open pull requests without merging, preserving review and Actions evidence.

3.5 A5 — Test-suite optimisation

Duplicate criterion: two cases are exact duplicates only when they use the same operation, the same complete pre-state and concrete inputs, and require the same result/exception and state-change assertions. Sharing a requirement or expected status is not enough.

No exact duplicates were found across ECP, BVA, and decision-table suites. Similar-looking cases differ in credits, dues, capacity, enrollment, prerequisites, or priority conditions. Exact duplicate count = 0; cases removed = 0; all 55 design cases retained with their IDs and technique traceability.

4. Part B — White-box testing

4.1 B1 — CFG, cyclomatic complexity, and basis paths

The CFG expands Python short-circuit and chained comparisons into atomic predicate nodes. registration_decision() has 9 atomic decision nodes: D1 (negative dues), D2a/D2b/D2c (capacity guard), D3 (dues), D4 (duplicate), D5 (prerequisites), D6 (credit limit), and D7 (availability).

MethodCalculationResult
Predicate nodes + 1P = 9 atomic predicatesV(G) = 9 + 1 = 10
Graph theoryN = 1 entry + 9 decisions + 8 terminals + 1 virtual exit = 19; E = 27V(G) = 27 − 19 + 2 = 10
Regions9 bounded regions + 1 outer regionV(G) = 10

Counting each source if once gives 7 decisions and V(G) = 8. The report explicitly uses the short-circuit-expanded convention so the CFG, condition table, and basis paths are consistent. The CFG image is docs/cfg.png.

4D1(F) → D2a(F) → D2b(F) → D2c(T) → raiseWB-CC-05ValueError("Invalid capacity or enrollment")

Before correction, path 9 was infeasible because D2b rejected enrolled > capacity and D7 tested the wrong condition. After the FR-08 fix, D7 tests enrolled >= capacity and all 10 basis paths are executable.
